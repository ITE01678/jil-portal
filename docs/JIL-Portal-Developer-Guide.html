01 — Overview

Project Overview

The JIL Portal is a single-page React application that serves two distinct audiences from one codebase: a public company website for jil-jupiter.com visitors, and a private employee intranet secured by Microsoft Entra ID (Azure Active Directory).

┌─────────────────────────────────────────────────────────────────┐ │ JIL Portal SPA │ │ │ │ PUBLIC SIDE (no login required) │ │ ├── Home · About · Products · Manufacturing │ │ ├── Beyond Profit · Investor Relations │ │ ├── Media · Careers · Contact Us │ │ │ │ EMPLOYEE SIDE (Microsoft login required) │ │ ├── Dashboard (KPIs + SharePoint live data) │ │ ├── Forms Hub (HR / Finance forms) │ │ ├── Teams Chat (embedded Microsoft Teams) │ │ ├── Fun Zone (games + leaderboard) │ │ └── Infrastructure (IT systems + status) │ └─────────────────────────────────────────────────────────────────┘ │ │ ▼ ▼ GitHub Pages Microsoft 365 (static hosting) (Azure AD · SharePoint · Graph API)
🏢

Public Website

9 pages covering the full company story — products, milestones, media library, careers, and contact form with email notification.

🔐

Employee Portal

5 protected pages accessible only to JIL Microsoft 365 accounts. Secured by Microsoft Entra ID OAuth2 PKCE flow.

📊

Live SharePoint Data

Dashboard pulls real-time data from SharePoint lists: Leaderboard, Awards, News & Activities, and cross-device user presence.

04 — Routing

Routing Architecture

React Router v6 with two nested layouts. All /employee/* routes are wrapped in an auth guard — unauthenticated users are redirected to Microsoft login.

// App.jsx — route tree
BrowserRouter basename="/jil-portal/"   // GitHub Pages subpath
  └── Routes
       ├── PublicLayout                  // Header + Footer (no auth)
       │    ├── /                → Home
       │    ├── /about           → About
       │    ├── /products        → Products
       │    ├── /manufacturing   → Manufacturing
       │    ├── /beyond-profit   → BeyondProfit
       │    ├── /investor-relations → InvestorRelations
       │    ├── /media           → Media
       │    ├── /careers         → Careers
       │    └── /contact         → Contact
       │
       └── EmployeeLayout               // Sidebar + Header + PresenceProvider
            └── AuthGuard              // Redirects to MSAL login if not authenticated
                 ├── /employee/dashboard      → Dashboard
                 ├── /employee/forms          → Forms Hub
                 ├── /employee/chat           → Teams Chat
                 ├── /employee/fun            → Fun Zone
                 └── /employee/infrastructure → Infrastructure
SPA routing on GitHub Pages: A 404.html redirect trick or the peaceiris/actions-gh-pages action handles deep-link refreshes. Any URL hit directly is redirected to index.html which React Router then resolves client-side.

import { PublicClientApplication } from "@azure/msal-browser";
import { AZURE_CREDENTIALS } from "./azureConfig";

export const msalInstance = new PublicClientApplication({
  auth: {
    clientId:    AZURE_CREDENTIALS.clientId,
    authority:  `https://login.microsoftonline.com/${AZURE_CREDENTIALS.tenantId}`,
    redirectUri: AZURE_CREDENTIALS.redirectUri,
  },
  cache: { cacheLocation: "sessionStorage" }, // Cleared on tab close
});

How Graph API Calls Work

// services/graphClient.js
async function graphFetch(path, options = {}) {
  // 1. Silently acquire token (uses cached token or refreshes automatically)
  const token = await msalInstance.acquireTokenSilent({
    scopes:  graphRequest.scopes,
    account: msalInstance.getAllAccounts()[0],
  });

  // 2. Call Graph API with Bearer token
  const res = await fetch(`https://graph.microsoft.com/v1.0${path}`, {
    ...options,
    headers: { Authorization: `Bearer ${token.accessToken}`, ...options.headers },
  });

  if (res.status === 403) throw new Error("[Graph 403] Permission denied");
  return res.json();
}

07 — Presence

Presence System

The "Online Users" pill in the employee header shows who is currently using the portal. It operates in two modes depending on SharePoint availability.

🟢 LIVE MODE (cross-device)

Active when SharePoint is configured & admin consent granted.

  • Writes heartbeat to "JIL Active Sessions" SharePoint list every 60s
  • Polls the list every 60s to get all active users
  • Works across any device, browser, or location
  • Session tracked by stable sessionStorage UUID
  • Row marked inactive on tab close (beforeunload)

🟡 FALLBACK MODE (browser only)

Active when SharePoint is not configured or returns 403.

  • Uses localStorage keyed by MSAL localAccountId
  • Uses BroadcastChannel for real-time sync across tabs
  • Only shows users in the same browser on same device
  • "Away" = last seen > 90s, "Offline" = last seen > 5 min
// PresenceContext.jsx — mode selection logic
const SHAREPOINT_READY = siteId !== "REPLACE_WITH_SITE_ID";
const useGraphPresence = SHAREPOINT_READY && !!account; // account = MSAL user

// On 403 (admin consent not yet granted): auto-retry once with forceRefresh
try {
  await msalInstance.acquireTokenSilent({ scopes, account, forceRefresh: true });
  await doJoin(); // retry after token refresh
} catch {
  setPresenceError("consent"); // shows admin consent link in UI
  localHeartbeat();            // fallback to localStorage
}

11 — Setup Guide

Complete Setup Guide

Follow these steps in order to go from zero to a fully working portal with live SharePoint integration.

Prerequisites

Node.js

v18+ required. Install from nodejs.org

Microsoft 365

Any M365 Business or Enterprise plan with SharePoint Online

Azure Access

Azure Portal access (portal.azure.com) to register the app

GitHub Account

To host the repo and use GitHub Actions + Pages

Step 1 — Clone and install

git clone https://github.com/ITE01678/jil-portal.git
cd jil-portal
npm install

Step 2 — Azure App Registration

  1. 1
    portal.azure.com → Azure Active Directory → App Registrations → New Registration
  2. 2
    Name: "JIL Portal" · Supported account types: "This organizational directory only" · Redirect URI: Single Page Application → http://localhost:5173
  3. 3
    Copy Application (client) ID and Directory (tenant) ID → paste into azureConfig.js
  4. 4
    API Permissions → Add → Microsoft Graph → Delegated → User.Read, Sites.ReadWrite.All, Files.ReadWrite.All
  5. 5
    Grant admin consent for the tenant (the blue "Grant admin consent" button in API Permissions)

Step 3 — Configure azureConfig.js

// azure-app-registration/azureConfig.js
export const AZURE_CREDENTIALS = {
  tenantId:    "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",  // Directory ID
  clientId:    "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",  // Application ID

npm run dev          # starts at http://localhost:5173
